## Clearer errors, safer CLI, steadier tests

v0.42.0 makes refusals and mistakes visible: a 403 says what was refused and why, misspelled keys come back as warnings instead of being silently ignored, and the CLI stops guessing. It has one breaking change, to sign-up.

## Breaking

- **Registering an email that already has an account answers 409** `{"error":"Email already registered"}`. It used to answer 200 with the existing user's id and email the owner a reset link. Login and password reset still answer the same for known and unknown emails. **Upgrade:** treat 409 from `register` as "this email has an account; sign in or reset the password".

## Added

- **403s say what and why:** `{"error":"Forbidden","code":403,"operation":"create","reason":"not_signed_in"}`. Reasons are `not_signed_in`, `rule_denied`, `admin_only` and `token_invalid`. The rule itself is never included.
- **`token_invalid`:** a request with a Bearer token the server didn't accept (expired, revoked, malformed) says so. From 0.44 it answers 401.
- **`Vaultbase-Warning` header** for an unknown `sort`, `expand` or `fields` name, or a body key that isn't a field. They are still ignored for now and become 400 in 0.44. Realtime subscriptions to a collection that doesn't exist get a `warning` frame.

## Changed

- **Unknown CLI commands and options are refused** (`vaultbase serve`, `vaultbase --port 9000`) with exit code 2, instead of starting a server on the default port.
- **`vaultbase mcp` and `vaultbase token`** refuse a folder with no install instead of creating an empty `vaultbase_data`, and name the folder they opened.
- **`setup-admin` and the password pages** follow the password policy (12+ characters by default).
- **`token mint`** rejects unknown scopes.
- **Cluster mode** prints a deprecation warning at start, and the admin shows a banner while it runs. It still works; a later release removes it.

## Fixed

- **A second server on a busy port** stops with "port … is already in use" instead of starting beside the first one.
- **The startup line shows the data folder and the database.**
- **The installer** keeps working when GitHub's "latest release" page fails, by asking GitHub's API.
- **Admin:** the MCP page's local-binary config uses this server's real paths; the records page's "API rules" and "Indexes" tabs open the right tab.

## Tests and releases

- The test suite no longer relies on fixed sleeps, and a nightly job hunts for flaky tests.
- Releases now wait for CI on the tagged commit, need the maintainer's approval, and smoke-test the published Linux binary.

## SDKs

- **JS SDK 0.11.0** reports an expired session as `auth`/`expired` (it used to sign out silently and report `forbidden`), adds the `not_signed_in` reason, a `not_found` kind for 404 and `validation` for 400, and passes server warnings to `console.warn` in development or to an `onWarning` callback. `not_found` is a new error kind: a TypeScript `switch` that handles every kind needs a case for it.
- Dart `vaultbase` 0.6.0 and `vaultbase_flutter` 0.1.5 work with this release. Handle the new 409 from `register` as with any other API error.

See the [changelog](https://docs.vaultbase.dev/changelog/) for the full list.

## Upgrade notes

- **Sign-up:** handle 409 from `register` (see Breaking).
- **Scripts:** a script that passed arguments `vaultbase` ignored now fails with exit code 2. Remove them, or use the environment variables (`VAULTBASE_PORT`, `VAULTBASE_DATA_DIR`).
- If you are coming from before [v0.40.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.40.0), its upgrade notes apply.
