## File uploads in the admin, and a realtime fix

v0.26.2 lets you upload, replace and remove files from a record's form in the admin, brings the admin's modals and drawers in line with the redesign, and fixes singleton updates not reaching non-admin subscribers.

## Admin

- **Files in the record form.** File fields get an Upload / Replace / Add files button (following the field's allowed types and `multiple`), a remove button on each file, and a preview of what you picked. The change is saved with the record.
- **Modals, drawers and the confirm dialog match the redesign**: square, with a header like the page bars. Escape or a click outside closes the topmost one. Dropdown panels match too.

## Fixes

- **Singleton updates reach everyone who can read them.** `vb.subscribe("settings", "*")` only told admins about changes to a singleton; its view rule alone decides now.
- **`?filter=author.name="Ada"` is a 400, not a 500.** A dotted path reads inside a `json` field. Filters don't follow relations: compare the relation's id, or use `@collection`.
- **A non-multipart upload is a 400, not a 500**, on file uploads and backup restore.

## SDK

- **0.7.2:** realtime callbacks get only their own collection's events, and every one of them. 0.7.1 handed each `vb.subscribe(name, "*")` callback every collection's events, and dropped a record's second update within a second. Use `vb.subscribe("*", "*")` to hear everything. `FileMeta` and `UploadOptions` are exported.

## Upgrade notes

- With SDK 0.7.2, a `vb.subscribe(name, "*")` callback no longer receives other collections' events. If you relied on that, subscribe to `"*"`.
