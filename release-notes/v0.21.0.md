## Index suggestions and composite indexes

v0.21.0 adds a list-query view to the Monitoring page that names the index a slow list needs, lets the indexes API and admin UI create multi-field indexes, and trims work from the request path. No configuration changes.

## Changes

- **List queries on the Monitoring page.** Every record list is recorded by its shape (collection, filter, sort, deep page, search) with call count, mean, max and total time. The panel lists shapes by total time with SQLite's query plan, flags the ones that read a whole table without an index or sort in memory, and for tables of 1,000+ rows names the index that would serve them, with a button to create it. `GET /api/v1/_/metrics/queries` returns the same report.
- **Composite indexes.** `POST /api/v1/admin/collections/<name>/indexes` takes `fields: [...]` (up to four, in index order); the list endpoint returns each index's `fields`. The Indexes tab builds multi-field indexes. Put the fields a list filters on with `=` first, then the one it sorts by.
- **Request authentication verifies tokens synchronously** with an HMAC in-process; revocation and principal checks still hit the database on every request.
- **Per-request lookups are cached on the read path**: settings (2 s, dropped at once by a write through the settings API), parsed field lists, table columns, private-field sets and per-field decoders.
- **Fixed:** parallel refreshes of one token all get the same replacement instead of the losers being signed out.
- **Experimental, off by default:** `VAULTBASE_READ_WORKERS=<n>` serves record reads on worker threads. See the changelog for what is still missing before it is fit for production.

## Upgrade notes

- Settings written directly to the `vaultbase_settings` table by something other than the settings API or the CLI can take up to two seconds to be seen by a running server.
- A field list returned by the server's own read path is frozen; an extension that modified a collection's parsed fields in place will now get an error and should copy first.
