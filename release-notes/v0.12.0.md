## Upgrade notes

v0.12.0 fixes several security and data-integrity bugs. A few of the fixes change behaviour you may notice:

- **Uploads are capped at 50 MB per request by default.** Larger uploads get `413`. Change it in Settings → File storage → Max upload size (up to 128 MB, the server's request body limit). A file field's own max size still applies on top.
- **`perPage` is capped at 500** on the list and batch endpoints. Invalid `page` / `perPage` values (negative, zero, non-numeric) fall back to page 1 / 30 per page instead of returning the whole table or a 500.
- **A list rule that can't be evaluated now returns `403`.** Previously a broken rule (or a valid `@collection` / `_via_` rule right after a restart) was silently dropped and non-admins got every row. An invalid `?filter=` now returns `400` instead of being ignored. If you see new 403s on a collection, check its list rule.
- **Impersonation tokens can no longer be refreshed** (`/auth/refresh` returns `403`); impersonation sessions stay time-boxed.

## Fixes

- **List rules fail closed** — broken or cold-cache rules no longer expose all rows.
- **Token refresh** — refreshed user tokens kept only `id` and `email`, so every refresh logged the user out. Anonymous users stay anonymous.
- **Batch requests** — writes from other requests no longer get swept into (and rolled back with) a batch's transaction; concurrent batches no longer fail with `cannot start a transaction within a transaction`; realtime events, webhooks and after-hooks fire only for committed batches.
- **Webhooks** are claimed before sending: a slow receiver no longer gets the same delivery on every 2 s tick, and cluster workers don't double-send.
- **Cron jobs** run once per slot: a job slower than the 30 s tick no longer starts again, and `vaultbase cluster` no longer runs each job once per worker.
- **Realtime** accepts non-browser clients without an `Origin` header again (server-side SDK); a present `Origin` must still be allow-listed.
- `vaultbase --help` / `--version` exit instead of hanging.

## Smaller downloads

- Linux binaries drop from ~118 MB to ~89 MB: built on Bun 1.4.2, and the admin UI is embedded once instead of three times.
- Each Linux binary also ships as `.xz` (~30 MB). The installer downloads it when `xz` is available and verifies the decompressed binary against the same `.sha256` / cosign signature.
