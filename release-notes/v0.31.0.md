## Leave fields out of record responses

v0.31.0 adds `exclude`, the opposite of `fields`, and fixes two ways a batch read differed from the same REST call.

## New

- **`exclude` leaves fields out of record responses** ([#6](https://github.com/vaultbase-sh/vaultbase/issues/6)). `?exclude=body,meta` returns every field but those, so a list can skip a few large fields without naming all the others. It applies after `fields` (`?fields=title,body&exclude=body` returns `id` and `title`), `id` is always returned, and `exclude=expand` drops expanded relations. It works on lists, get-one, singletons, batches and the MCP list tool. The JS and Dart SDKs take it as an option from their next releases.

## Fixed

- **A `GET` of one record in a batch ignored `expand` and `fields`.** It now shapes the record as the REST get-one does.
- **A batch list on a collection with a public list rule expanded relations without the request,** so a related collection's view rule reading `@request.headers` or `@request.query` could decide differently than the same REST list.

See the [changelog](https://docs.vaultbase.dev/changelog/) for everything.
