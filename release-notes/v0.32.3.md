## Files behind a CDN, and CLI commands on an installed server

v0.32.3 stops a CDN from caching files the server decided per caller, and makes `vaultbase` commands run by hand safe on an installed server. It comes with two new deployment recipes: [a plain VPS](https://docs.vaultbase.dev/guides/recipe-vps/) and [behind Cloudflare](https://docs.vaultbase.dev/guides/recipe-cloudflare/).

## Fixed

- **A CDN in front of the server could keep a file and serve it to anyone.**
  - Files were sent without `Cache-Control`. A CDN such as Cloudflare caches images, PDFs and other static file types by default, keyed on the URL.
  - So a file a view rule allowed for one caller could be served to others, and one-time or IP-bound file tokens worked again from the cache.
  - Files are now sent `private`, `private, no-store` when served by a token, and errors `no-store`.
- **`sudo vaultbase setup-admin` could stop the service from starting.**
  - Run as root, it left a root-owned file in the data directory that the service, running as its own user, couldn't read at its next start.
  - `setup-admin`, `doctor`, `backup`, `token` and `wipe` now refuse to run as root on a data directory another user owns, and print the command to run instead: `sudo -u vaultbase vaultbase …`.
- **`doctor`, `backup`, `token` and `wipe` ignored the service's env file** and worked on `./vaultbase_data` in the current directory. They read `/etc/vaultbase/vaultbase.env`, as `setup-admin` does, and say when it's there but can't be read.
- **The request log and the metrics showed a refused admin call as `200`.** They record the status the response went out with.

See the [changelog](https://docs.vaultbase.dev/changelog/) for everything.

## Upgrade notes

- If the service fails to start with "database.json can't be read" after a `sudo vaultbase …` command, run `sudo chown -R vaultbase:vaultbase /var/lib/vaultbase` and start it.
- Run `vaultbase` commands on an installed server as the service's user: `sudo -u vaultbase vaultbase doctor`.
- Upgrade notes for earlier releases apply if you are coming from before [v0.30.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.30.0).
