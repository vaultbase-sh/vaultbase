## Bun 1.4.4

v0.34.1 moves the server to Bun 1.4.4 and keeps the GIF thumbnail limits working on it.

## Changed

- **Built on Bun 1.4.4** (was 1.4.2).
  - Postgres queries use less CPU, idle servers use less, and S3 uploads no longer hold the whole file in memory.
  - The binaries are about 28 MB larger, about 15 MB more to download. All of it is the Bun runtime.

## Fixed

- **GIF thumbnails measure the canvas from the file.**
  - Before decoding an animated GIF, the server checks how much memory the frames will take, so a small file can't make it decode gigabytes.
  - That check used the size reported by the image library. Bun 1.4.4 reports the first frame's size there, not the canvas, so a file with tiny frames on a huge canvas would have passed.
  - The canvas now comes from the GIF's own header, widened to cover every frame. Files over the limit get a first-frame thumbnail, as before.

See the [changelog](https://docs.vaultbase.dev/changelog/) for everything.
