## A full review, fixed

v0.36.0 is the result of a full review of the server, the admin and both SDKs: security fixes, correctness fixes across jobs, webhooks, rules and backups, faster paths, and less code. Backups no longer hold up the server while they run.

## Security

- **Old one-time links stopped working after a password reset or an email change.** An earlier reset link, a sign-in code or a link sent to the old address could still take the account back. Links are also spent before they act, so two requests can't both use one.
- **MCP:** a collection named like an admin tool (`hook`, `setting`, …) took over that tool, so `delete_hook` deleted a record; `list_webhooks` returned signing secrets to read-only tokens; `vaultbase mcp` (stdio) never re-checked its token.
- **Errors no handler answered** went out as plain text with the raw message (table and column names) and without CORS headers. They're JSON now, and server errors stay in the log.
- **File uploads and deletes** checked `update_rule` without the request, and a protected file's rule could read credential headers every other rule hides.

## Fixed

- **Jobs and queues:** a job whose result couldn't be written stayed "running" for good; cron runs longer than their interval re-ran slots across servers; retries are capped at a day; hooks, routes and workers run in a fixed order (routes most specific first).
- **Webhooks:** the timeout covers reading the response, a late attempt can't overwrite a newer one, and at most 64 run at once.
- **Collections:** a rename refused by a later check no longer leaves the collection broken; OAuth sign-in works in more than one auth collection; unique `date` and `json` fields are checked on their stored form.
- **Rules agree between lists and single records:** `%`/`_` wildcards, text comparison, `@request.auth.id = null`, and `~` on numbers on Postgres.
- **Backups:** a failed write no longer blocks later backups, and a restarted container no longer finds its own stale lock.
- **Several servers on one database:** setting changes no longer wipe every server's thumbnails.
- **Record history** keeps writes in order within a second; **row counts** stay right after `REPLACE`.
- **Feature flags:** rollouts reach the share they're set to (a 10 % rollout reached about 11 %).
- **Admin:** an unreachable server shows a retry screen instead of a blank page; switching collections no longer carries the previous one's filter; unsaved hook code isn't lost on Escape; and more.

## Faster

- **SQLite backups run in a background thread**: before, every write, sign-in and admin request waited for the copy.
- S3 downloads and the backup download stream instead of buffering; the log reader, settings, vector search and the SQL page do less work per request.

## SDKs

JS SDK 0.10.0 and Dart `vaultbase` 0.6.0 (with `vaultbase_flutter` 0.1.5) ship with this release: a refresh that can't be answered keeps the session, realtime backs off properly and stops on a refused origin, ETags aren't cached from errors, and type generation handles any collection name.

See the [changelog](https://docs.vaultbase.dev/changelog/) for the full list.

## Upgrade notes

- **Feature flags:** the rollout fix moves some users into a different bucket once.
- **MCP:** tools of a collection named like an admin tool get a `_records` suffix (`vaultbase.delete_hook_records`).
- **Errors** are always JSON; a request body that fails a route's schema answers `{ "error", "code": 422, "details" }`.
- **Custom routes** match the most specific path first; **hooks** run oldest first.
- **Multiple relations:** a new relation with `options.multiple` is refused; existing ones are kept.
- The first start adds a column to the record history table and replaces the OAuth link index. Both are automatic.
- Upgrade notes for earlier releases apply if you are coming from before [v0.30.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.30.0).
