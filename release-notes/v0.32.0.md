## Group fields

v0.32.0 adds `group`, a field type for structured items whose shape the schema declares: line items on an order, an address book on a user, the steps of a recipe.

## New

- **Group fields.** Declare the subfields (text, number, bool, select, email, url, date, color, editor, json) and the field holds a list of items, each checked as top-level fields are. Unknown keys are refused, and errors name the item (`items[2].qty must be at least 1`).
  ```json
  { "name": "items", "type": "group", "options": { "min": 1, "max": 100, "fields": [
      { "name": "sku", "type": "text", "required": true },
      { "name": "qty", "type": "number", "required": true, "options": { "min": 1 } }
  ] } }
  ```
  - Every item gets an `id` from the server, kept when you send the item back.
  - `multiple: false` stores one object instead of a list, such as an address.
  - Renaming a subfield keeps its values, and removing one deletes them, in the same transaction as the schema change.
- **Filters and rules over items.**
  - `items.qty ?> 2`: some item.
  - `items.qty:each > 0`: every item.
  - `items:length > 0`: the item count.
  - `items:any(sku = "A-1" && qty > 2)`: one item that meets every condition.

  Values compare by JSON type, and list queries, realtime and single-record checks give the same answers on SQLite and Postgres.
- **Everywhere else.** The admin edits items as cards and shows group subfields in the schema editor. OpenAPI, the MCP tools and seed, and CSV import and export support it. The JS SDK's `vb-types` and the Dart SDK's `dart run vaultbase:types` type it from their next releases.

## Changed

- **Filters over `json` fields:**
  - `?=` and `:each` on a value that isn't a list match nothing. They failed on Postgres, and on SQLite one value counted as a one-element list.
  - A path through text (`meta.a.b` where `meta.a` is a string) is no value. It failed the query on SQLite.
  - `:length` on a JSON path counts a list's elements or a string's characters.

See the [changelog](https://docs.vaultbase.dev/changelog/) for everything, and the [field reference](https://docs.vaultbase.dev/reference/field-types/#group) for group fields.

## Upgrade notes

- Nothing to do. Check filters on `json` fields against the changes above if they relied on the old answers. Upgrade notes for earlier releases apply if you are coming from before [v0.30.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.30.0).
