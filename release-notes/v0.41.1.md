## File uploads work again

v0.41.1 fixes file uploads, CSV import and one-request restores, which had failed since v0.38.0. Upgrade if you upload files.

## Fixed

- **File uploads, CSV import and the one-request restore work again.** Since [v0.38.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.38.0), every upload to `POST /api/v1/files/...` (from the SDKs, the admin or `curl`) answered 400 "Send the file as multipart/form-data", CSV import answered 500, and a restore uploaded in one request answered "No file uploaded". The rate limiter's batch check made the server read every request's body before the route did. The batch route now charges its ops itself, and batches are still charged per op. Chunked restore uploads were not affected.

## Tests

- Uploads, CSV import, restore and batch rate limiting are now tested through the whole server.

## SDKs

No SDK release is needed. JS SDK 0.10.0, and Dart `vaultbase` 0.6.0 with `vaultbase_flutter` 0.1.5, work with this release.

See the [changelog](https://docs.vaultbase.dev/changelog/) for the full list.

## Upgrade notes

- None. If you are coming from before [v0.40.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.40.0), its upgrade notes apply.
