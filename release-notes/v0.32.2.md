## Sign-up hooks on every sign-up

v0.32.2 runs `beforeCreate` hooks on OAuth sign-up, guest sign-in and guest upgrade, as register and invitations already did.

## Fixed

- **OAuth sign-up, guest sign-in and guest upgrade skipped `beforeCreate` hooks.** A hook that refused some addresses or set fields at sign-up was bypassed on those paths. They run it now, and what it changes is validated.
  - **OAuth and native ID-token sign-up:**
    - The provider's name and address never block a sign-in; a name the collection's field refuses is left out.
    - An address the hook sets is used when it's free (`409` otherwise), including a change in case only.
    - That address counts as verified only if it's the provider's verified address.
  - **Guest sign-in:** the hook may refuse guests or set fields. The generated address can't be changed.
  - **Guest upgrade (`/promote`):** the hook gets the guest's record as `ctx.existing` and the guest's session as `ctx.auth`. It may change the address, which is then checked for an existing account.

See the [changelog](https://docs.vaultbase.dev/changelog/) and [sign-ups on auth collections](https://docs.vaultbase.dev/concepts/hooks/#sign-ups-on-auth-collections).

## Upgrade notes

- `beforeCreate` hooks on auth collections now also run on OAuth sign-up, guest sign-in and guest upgrade.
  - A hook written for `/register` only may see bodies without the fields it expects, since OAuth and guests set few, or it may refuse those sign-ups.
  - To treat them differently, check `ctx.existing` (set on guest upgrade) or the record's fields.
- Upgrade notes for earlier releases apply if you are coming from before [v0.30.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.30.0).
