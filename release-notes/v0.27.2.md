## Settings writes survive a background refresh

v0.27.2 fixes a settings bug on Postgres found by an intermittent CI failure.

## Fixes

- **On Postgres, a setting written for the first time could read as unset for up to 2 seconds.** The settings store refreshes from the database every 2 seconds, on another connection. A refresh that started while a write was in flight didn't see the new row and dropped the value from memory until the next refresh. A refresh now keeps the values whose writes were in flight when it started.

## Upgrade notes

- Nothing to do. The upgrade notes for [v0.27.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.27.0) apply if you are coming from an earlier version, in particular: reads count toward rate limits again.
