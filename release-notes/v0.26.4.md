## An admin UI pass, and the server fixes it turned up

v0.26.4 comes out of driving every admin page in a browser. Most fixes are in the admin; several are on the server, including two security fixes.

## Security

- **A hook egress deny list made of typos is refused.** Bad entries were dropped silently, so a list of only bad entries left no deny rules at all. Egress lists, trusted proxies, the lockout duration, CORS max-age and the SMTP From are now validated when you save.
- **Admin emails ignore case**, so `ops@` and `OPS@` can't be two accounts.
- **The audit log credits a password change to the admin who made it** (it was recorded as anonymous).

## New

- **Webhook redelivery**, from the delivery drawer or `POST /api/v1/admin/webhooks/<id>/deliveries/<deliveryId>/redeliver`.
- **Feature-flag segments** in the admin, and a JSON editor for rules that use `any`, `not`, segments or prerequisites.

## Fixes

- **Log JSONPath search** searches every entry; it looked at the newest 500 only.
- **Feature flags:** saving in the admin no longer drops `any` / `not` / segment rules, and `"02134"` stays text.
- **Cron** refuses a seconds field, which the once-a-minute scheduler couldn't honour.
- **Webhooks:** a test on a disabled webhook says so instead of reporting success.
- **Storage and SMTP tests** show why they failed.
- **Admin UI:** records save empty values as null, record history and restore, the theme colours the whole admin, real port and data directory on the Application tab, view errors shown as text, number inputs that don't fight your typing, ⌘↵ in the SQL editor, fonts that load, and many smaller fixes.

## Upgrade notes

- **Cron jobs with six fields** (a seconds field) are refused when created or edited. Existing ones keep their schedule; rewrite them with five fields.
- **Settings validation:** saving an invalid egress list, trusted proxy, lockout under 60s, negative CORS max-age or malformed SMTP From is now a 422. Values already stored are unchanged.
- **Admin emails** are matched without regard to case. Two existing admins that differ only in case both still sign in (an exact match wins); no new admin or email change can collide with them.
