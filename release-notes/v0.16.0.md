## Security and account flows

v0.16.0 fixes session handling on password changes and the hosted auth pages, and adds email change and invitations. Upgrade if your users reset passwords or use the email links.

## Security fixes

- **Password reset now ends existing sessions.** Before, a stolen token kept working after the owner reset their password. Changing an admin's password now ends that admin's sessions too.
- **The hosted `/auth/*` pages put the link's `token` / `collection` values into an inline script unescaped.** The site's Content Security Policy blocked the injection; the values are now escaped.

## Fixes

- **The hosted `/auth/reset`, `/auth/verify` and `/auth/otp` pages now work.** The site-wide CSP blocked their inline scripts, so the reset form, email verification and magic-link pages did nothing in a browser. Each page now sends its own nonce-based CSP.
- SMTP connect and greeting time out after 15 seconds instead of hanging for minutes.
- Very long request paths and hook log messages are truncated in log lines (2 KB / 8 KB).

## New

- **Email change.** `POST /api/v1/auth/<col>/request-email-change` emails a link to the new address. `confirm-email-change` applies it with the current password, marks the new address verified and ends existing sessions. Hosted page: `/auth/confirm-email-change`.
- **Invitations.** `POST /api/v1/admin/users/<col>/invite` creates a user without a usable password and emails a 7-day link. `accept-invite` sets the password and verifies the email. In the admin: **Records → Invite user** on auth collections. Hosted page: `/auth/invite`.
- SDK (`@vaultbase/sdk` 0.5.0): `vb.auth.<col>.requestEmailChange()`, `.confirmEmailChange()`, `.acceptInvite()`, `vb.auth.admin.invite()`.

## Upgrade notes

- **Orphaned files are deleted.** An hourly sweep removes stored files and their thumbnails once they are 24 hours old and their record or collection is gone, their field was dropped, or the record no longer names them. Collections with record history are skipped. Set `files.orphan_cleanup` to `0` to keep the old behaviour.
- **Request-log files follow data retention.** Daily `logs/*.jsonl` files older than `maintenance.retention_days` (default 30) are deleted. Set it to `0` to keep them all.
- **Changing an admin's password signs that admin out everywhere**, including the session that made the change.
