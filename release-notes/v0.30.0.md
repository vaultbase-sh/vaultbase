## Postgres is out of beta

v0.30.0 makes Postgres a full choice next to SQLite, adds a check for unencrypted database connections, and fixes WAL growth on SQLite under nonstop writes.

## Changed

- **Postgres is out of beta.** The whole product runs on it, backups and restore included, and the full test suite runs on Postgres 16, 17 and 18 on every change. The docs now cover [Postgres setups](https://docs.vaultbase.dev/guides/deployment/#postgres): on one machine, a managed database with TLS, and several servers behind a load balancer. The [Performance page](https://docs.vaultbase.dev/guides/performance/#sqlite-and-postgres) compares the two databases on the same machine. The database is still chosen once, at install.

## New

- **`vaultbase doctor` warns when the connection to a database on another machine isn't encrypted.** Without `sslmode` in `VAULTBASE_DATABASE_URL`, Bun's Postgres driver doesn't use TLS even when the server offers it, so a URL copied without it ran in plain text. Use `sslmode=require`, or `verify-full` with the CA in `NODE_EXTRA_CA_CERTS`.

## Fixed

- **SQLite: under nonstop writes the WAL could grow to hundreds of megabytes.** The background checkpointer could lose the write lock it needs every time. After 2 seconds of lost attempts, the main thread now rewinds the log itself between two of its writes.

See the [changelog](https://docs.vaultbase.dev/changelog/) for everything.

## Upgrade notes

- On Postgres, run `vaultbase doctor` after upgrading and add `sslmode` to the URL if it warns about encryption.
- Upgrade notes for earlier releases apply if you are coming from before [v0.29.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.29.0).
