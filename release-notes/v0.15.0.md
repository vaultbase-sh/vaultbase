## Search, aggregations, image transforms and an OpenAPI spec

### Full-text search

Mark `text`, `editor`, `email` or `url` fields as **Searchable** in the collection editor and query them with `?search=` on the list endpoint:

```
GET /api/v1/posts?search=quick bro
```

Every word must match and the last one matches as a prefix, so it works for search-as-you-type. Matching ignores case and accents. Results are ordered by relevance unless you pass `sort`. Search combines with `filter`, pagination, the list rule and `nearVector`. It's backed by a SQLite FTS5 index kept in sync by triggers. Existing records are indexed when you turn the option on.

### Aggregations

```
GET /api/v1/orders/_aggregate?agg=count,sum(amount)&groupBy=status&sort=-sum_amount
GET /api/v1/users/_aggregate?groupBy=created:month
```

`count`, `sum`, `avg`, `min` and `max`, grouped by up to three fields or by time buckets (hour, day, week, month, year). Filter, search and the list rule apply, so callers only aggregate records they could list. SDK: `collection.aggregate()`.

### Image transforms

- `?format=webp|jpeg|png|auto` re-encodes an image, with or without `?thumb=`. `auto` serves WebP to browsers that accept it.
- `?quality=1-100` for JPEG and WebP.
- `?thumb=800x0` keeps the aspect ratio.
- File fields can list the **Thumbnail sizes** non-admins may request.

### OpenAPI spec

`GET /api/v1/openapi.json` describes the records, auth and files API as OpenAPI 3.1, generated from your collections. Load it in Swagger UI or Postman, or generate a client in any language. It's admin-only by default; **API preview → public spec** opens it, leaving out admin-only collections.

## Upgrade notes

- **Thumbnail variants are capped at 32 per file** for non-admin requests. Past the cap, new sizes, formats or qualities get the original file (`X-Vaultbase-Thumb: limit`). Cached thumbnails keep working. List your sizes in the field's **Thumbnail sizes** to make the set explicit.

## Security

- Anyone who could read an image could request unlimited distinct thumbnail sizes, each a fresh decode and a new cache file. The per-file cap above bounds that.

## Fixes

- `?thumb=WxH&fit=cover` ignored `fit` when sent as its own query parameter, which is the form the docs show.
