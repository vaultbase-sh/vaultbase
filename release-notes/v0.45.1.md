## Snapshots re-apply on Postgres, and `vaultbase update` checks permissions first

v0.45.1 fixes three bugs reported against 0.45.0. Upgrade if you apply snapshots on Postgres or keep auth collections in a snapshot.

## Fixed

- **Postgres: a snapshot with an index ending in `id` applies again.** The first apply made the index; every later apply of the same snapshot answered `An index named '…' already exists on other fields`, in both modes, and so did creating the index again in the admin. Postgres indexes end with `id` as a tie-break, and the index list cut that `id` off even when the index had been asked for with it. Indexes are listed with the fields they were asked for. The bug was in every release since 0.36.0.
- **Snapshots: an auth collection's built-in fields aren't a difference.** With a snapshot that leaves out `email` and `verified`, as a hand-written one does, `migrations/diff` reported `fields: 2 removed` on every run, additive apply listed the collection as skipped, and sync rewrote it each time.
- **`vaultbase update` checks that it may replace the binary before it asks and downloads.** For an install under `/usr/local/bin` run without `sudo`, it used to download the release and then fail on the last step. It now stops at once and says to run it again with `sudo`. The progress output no longer ends with a second `100% (0.0 / 0.0 MiB)` line.

## Good to know

- `POST /api/v1/admin/migrations/apply` answers `200` even when a collection failed to apply: each failure is in `data.errors`. A deploy script should check that `errors` is empty. This is now in the [docs](https://docs.vaultbase.dev/guides/backups/), and a later release will answer with an error status instead.

## SDKs

No SDK release is needed. JS SDK 0.11.1, and Dart `vaultbase` 0.7.1 with `vaultbase_flutter` 0.1.6, work with this release.

See the [changelog](https://docs.vaultbase.dev/changelog/) for the full list.

## Upgrade notes

- None. Upgrades are supported from v0.24.0; from an older install, upgrade to 0.24.x first.
