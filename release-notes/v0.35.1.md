## Security fixes

v0.35.1 is a patch release with seven security fixes found in a full review of the code. Upgrade from 0.35.0 by replacing the binary; there's nothing else to do, apart from the filter note below.

## Fixed

- **A realtime connection refused for its origin could shut the server down.** On the internal listener (Linux, with read workers), closing the refused socket threw outside any handler. It now closes quietly.
- **Rich-text (editor) fields: a tag left open could stall the server.** An unclosed quote inside a tag made sanitizing take time growing with the square of the input: about a minute for a 600 KB value. Everything from such a tag on is now kept as escaped text.
- **Thumbnails of very thin images could exhaust memory.** A 50000×1 image asked for at `0x4096` meant a 204-million-pixel resize. A resize whose output is over the 50-megapixel budget now serves the original instead.
- **An empty JWT secret was accepted.** `VAULTBASE_JWT_SECRET=` (set but empty) or an empty `.secret` file signed tokens with an empty key. Empty counts as unset now: the secret is read from, or written to, `.secret`. Cluster workers starting together on a fresh install also no longer end up with different secrets.
- **A view could expose a password field whose name has capitals.** Output hid it, but filters, sort and `_aggregate` `groupBy` on a `SELECT *` view accepted `PIN`, since the check compared names case-sensitively.
- **Filter and rule strings: a value ending in a backslash escaped its closing quote,** so the rest of the expression was read differently. `\\` is now one backslash, as the SDKs' filter builders already write it.
- **Two admins deleting each other at the same moment could both succeed,** leaving no admin. The count and the delete now run in one transaction that holds the admin rows.

See the [changelog](https://docs.vaultbase.dev/changelog/).

## Upgrade notes

- In filter and rule strings, `\\` now means one backslash. A stored rule that relied on `\\` meaning two needs `\\\\`.
- Upgrade notes for earlier releases apply if you are coming from before [v0.30.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.30.0).
