## Deleting a file clears it from the record

v0.27.3 fixes file deletes leaving a dangling file name on the record.

## Fixes

- **Deleting a file left the record's field naming it.** `DELETE /api/v1/files/{collection}/{id}/{field}/{filename}` (and the whole-field delete) removed the stored file but not its name from the record, so the record pointed at a file that answered 404. The name is now taken out of the field first, through the normal update path, so hooks, realtime subscribers and record history see the change. The last file of a required field can't be deleted; that request answers 422 and changes nothing.

## Upgrade notes

- Nothing to do. If you relied on a deleted file's name staying in the record, read the field after the delete. The upgrade notes for [v0.27.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.27.0) apply if you are coming from an earlier version, in particular: reads count toward rate limits again.
