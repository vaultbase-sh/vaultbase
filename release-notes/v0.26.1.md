## Get one record with expand and fields

v0.26.1 makes `GET /api/v1/<collection>/<id>` honour `expand` and `fields`, as the API docs and the OpenAPI spec always said it did.

## Fixes

- **Get-one takes `expand` and `fields`.** They were ignored: the record came back without expanded relations and with every field. Get-one now shapes the record exactly as a list does, so the related collection's view rule still decides what's expanded. Singletons take both too. ETags are unchanged.
- **`fields` keeps `expand`.** Asking for `?fields=id,title&expand=author` dropped the expansion, on lists as well. It's kept now when the request expands.

## SDK

- **0.7.1:** `vb.collection(name).get(id, { expand, fields })`. `vb.singleton(name).get({ expand, fields })` already sent them and now gets them applied.

## Upgrade notes

- A list or get-one with both `fields` and `expand` now includes `expand` in each record. If you relied on it being dropped, leave out `expand`.
