## Security release

v0.18.0 fixes four access-control issues found in a full-codebase security audit. **Upgrade, and read the upgrade notes first**: sign-up now follows each auth collection's create rule, and you should review those rules after upgrading.

## Security fixes

- **Sign-up ignored the create rule.** `/auth/:collection/register`, `/anonymous`, `/promote` and OAuth2 sign-up opened an account in any auth collection whatever its create rule said, and stored any of its custom fields from the request (a `role` field, for example). They now enforce the create rule exactly like the records API.
- **A file field value could redirect an admin's request.** A user who could edit a record with a protected file field could store a path such as `../../admin/users/…/disable-mfa?`; when an admin opened the collection, the admin UI sent an authenticated request to that endpoint. File field values must now be stored file names, and the admin UI encodes file URLs.
- **A lowercase key could fool a rule.** `@request.body.isApproved` read a decoy `isapproved` key first, so a rule could check one value while another was stored. Body and query keys are now matched exactly.
- **Filters could enumerate collections the caller can't list.** A `?filter=` reaching another collection through `@collection.*` or `_via_` only applied that collection's view rule, so records readable by id only (invite codes, a users list restricted to self) could be read out one character at a time. The list rule now applies too.

## Upgrade notes

- **Review your auth collections' create rule.** On the first boot after upgrading, auth collections whose create rule is **Admin only** are switched to **Public**, so sign-up keeps working as it did; the server logs which ones it changed. Set **Admin only** to close sign-up (invite-only collections), or a rule such as `@request.body.role:isset = false` to restrict what a sign-up may set. New auth collections still default to **Admin only**, which now really means no self-registration.
- **`@request.query.*` matches the parameter name exactly.** A rule that relied on a lowercased or hyphenated variant needs the exact spelling. `@request.headers.*` is unchanged.
- **Existing file field values that aren't stored file names** can't be saved again until corrected; the admin UI no longer requests tokens for them.
