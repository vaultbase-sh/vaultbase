## Singleton collections, every email template editable

v0.25.0 adds singleton collections, opens all five email templates to the admin editor, keeps the server responsive during very large realtime fan-outs, and tests upgrades from earlier releases in every build.

## New

- **Singleton collections.** A collection type with exactly one record, for site settings or app config. It's created with the collection, read with `GET /api/v1/<name>` and changed with `PATCH /api/v1/<name>`, with ETags and If-Match like any record. It can't be created again or deleted, over HTTP, in batches or through MCP. Only the view and update rules apply. In the admin, choose the Singleton type; its records page is a single form. SDK 0.7.0 adds `vb.singleton(name).get()` and `.update(data)`.
- **Every email template is editable.** Settings → Email templates now covers the email-change, invitation and sign-in code emails as well as verification and password reset, each with its variables listed and a Restore default button.

## Changes

- **Large realtime fan-outs no longer hold the server.** Who receives an event is decided once per event where possible, big fan-outs are sent a few milliseconds at a time so HTTP requests are served in between, and when realtime falls more than a few seconds behind, the waiting connections are disconnected so they reconnect, instead of latency and memory growing. New metrics: `vaultbase_realtime_connections`, `vaultbase_realtime_queued_deliveries`, `vaultbase_realtime_shed_connections_total`.
- **Upgrades are tested.** Databases made by seven earlier releases, back to 0.10.2, are booted by every build.

## Upgrade notes

- Under realtime overload, waiting connections are now disconnected. The SDK reconnects and re-subscribes on its own; refetch what you show after a reconnect, as after any disconnect.
