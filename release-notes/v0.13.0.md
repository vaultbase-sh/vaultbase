## Upgrade notes

v0.13.0 is mostly fixes and performance work, but a few changes are visible to existing installs. Read these before upgrading:

- **History cleanup.** A daily task now deletes finished queue jobs and finished webhook deliveries older than **30 days**. Change or disable it in **Settings → Data retention** (`maintenance.retention_days`, `0` keeps everything). Expired token revocations and one-time auth tokens are always cleaned up.
- **ETag format.** Record ETags are now `W/"<updated>-<content hash>"` so two writes in the same second get different tags. Old `W/"<updated>"` tags are still accepted on `If-Match`; on `If-None-Match` they no longer match (you get a fresh `200` instead of `304`). Treat ETags as opaque and send back what you received; the official SDK already does.
- **Unique fields.** Adding a unique field to an existing collection now works, and switching `unique` on enforces it in the database. Switching it on over duplicate data returns `422`. A field created as unique together with its collection can't have `unique` switched off in place (`422`); drop and re-add it.
- **Delete order.** `restrict` checks run first, then the `beforeDelete` hook, then cascades. A hook that refuses a delete now leaves the children untouched, and a cascading delete is atomic. Hooks that relied on children already being gone will see them.
- **Batches.** While a batch runs, other record writes wait for it to commit or roll back, and its realtime events / webhooks / after-hooks fire only after `COMMIT`. Batches with slow hooks delay other writes for that long.
- **Startup migrations.** First boot adds indexes on `created_at` / `updated_at` for every collection, indexes on file metadata, and three columns to the jobs log. Large collections take a moment longer to start the first time.

## Fixes

- **Collection rename** renames the table and its indexes and repoints relation fields, hooks and record history (it used to leave the collection unusable). Rules, webhook event patterns and API token scopes that mention the old name are free text; update them yourself.
- **Cascading deletes** are atomic and run after `beforeDelete`.
- **`helpers.enqueue` retry options** (`retries`, `backoff`, `retryDelayMs`) are now honoured.
- **Realtime** no longer accumulates empty topics, and a dead socket is dropped from all its topics.
- **Dependencies:** nodemailer 10 (clears all open Dependabot alerts), elysia 1.4.30, react-router 7.18, DOMPurify 3.4.16.

## Performance

- Record writes: hook / webhook / relation lookups cached — `createRecord` ~117 → ~64 µs.
- Default list sort and file lookups use indexes instead of full scans.
- Admin UI: Monaco and Quill load only where they're used — initial load ~5.8 MB → ~1.5 MB.
- Vector search: parsed vectors cached — repeat searches at 10k × 384 dims 158 → 13 ms.
- Logs page reads only new log lines on each poll (17.5 → 4.4 ms at 50k lines).
- Request logging no longer re-verifies the JWT per request (22 → 0.4 µs).
- Each uncached thumbnail is generated once, however many requests ask for it.
