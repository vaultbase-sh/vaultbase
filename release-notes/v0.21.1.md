## Read worker fixes

v0.21.1 fixes the experimental read worker threads shipped off by default in 0.21.0. No configuration changes. If you set `VAULTBASE_READ_WORKERS` on a 0.21.0 binary, remove it until you are on this version.

## Changes

- **A pool that fails to start no longer takes requests.** In 0.21.0, when `VAULTBASE_READ_WORKERS` was set and the workers could not start, the server logged it but still forwarded every record list and get-one to the missing workers, and those requests never answered. A pool that can't start now leaves nothing behind, a worker that dies is dropped with its in-flight requests failed, and a forwarded request that gets no reply within 30 s fails with 503 instead of hanging.
- **The worker is included in the compiled binaries.** 0.21.0's binaries could not start it at all; running from source worked. The build now compiles `src/read-worker.ts` as a second entry point.

The flag remains experimental: a collection or settings change made while the pool runs reaches the workers only after a restart, and the flag is ignored under `vaultbase cluster`.
