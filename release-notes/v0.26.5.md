## Relation fields are indexed

v0.26.5 comes out of running the load tests to the point of failure. The biggest find: relation fields had no index, so looking records up from the other side of a relation (a post's comments, a user's records) read the whole table.

## Fixes

- **Relation fields get an index.** `post = "<id>"` on 265k comments went from 56 ms to 1.2 ms. Existing collections are indexed once, the first time this version starts; new relation fields get one when they're added. In a mixed load test, throughput at 100 concurrent clients went from 466 to 761 req/s.
- **Dropping a field that has an index** (one added in the admin) works; it failed before.
- **Renaming a collection** renames the indexes added in the admin, not just the built-in ones.
- **Realtime over the connection cap** is refused with `503` and `Retry-After` before the WebSocket is set up, so turning clients away costs the server almost nothing.
- **MCP `create_collection`** with a name already in use says so.

## Upgrade notes

- **The first start builds the relation indexes.** On a large table that start takes a little longer than usual. The indexes are named `idx_vb_<collection>_<field>`, show up under the collection's Indexes tab, and can be dropped there; a dropped one isn't rebuilt.
