## Security fixes, checked again

v0.39.0 completes the security work started in v0.38.0. A fourth audit pass re-checked every fix in v0.38.0. Most held for the path they targeted, but several left a sibling path open. This release closes those paths, makes restore keep credentials, and fixes a dashboard stall. Upgrade soon. Several changes are visible after upgrading, so read the upgrade notes first.

## Security

- **Restore brings back data, not credentials.** Restoring a backup used to bring back:
  - a password changed after the backup, so a leaked password worked again;
  - email changes, MFA enrolment, spent recovery codes and provider links made since the backup;
  - admins deleted since the backup, together with their API tokens.

  Each account now keeps its current credentials, and admins deleted since the backup stay deleted. The restore's answer lists both, along with anything it couldn't carry over. Revocations and reset stamps carry over even if another step fails. An undo, or restoring a newer backup after an older one, keeps admins created since.
- **Every sign-in is bound to the reset it came after.** Magic-link, OAuth provider and API-token sessions now carry the reset stamp, as password sign-ins already did. So do the admin side of impersonation and the MFA steps. A reset that races any of them ends the session on every server. Push devices are disabled for users of every auth collection.
- **Hidden data on secondary paths:**
  - A join (`@collection`, `_via_`) reads only the rows its rule admits. On SQLite, a failing comparison could probe hidden rows.
  - A parameterized view's rules use the values the view is built with, never a batch's own URL parameters.
  - Singletons and views are hidden by the rules that apply to them, across the records API, batch, filters, file routes and the public OpenAPI.
  - File routes answer the same for a hidden collection or record as for a missing one.
  - File download tokens end with the session that minted them.
- **Views:** a change to a table that a view reads is refused (409) when that view would then expose a private column. Postgres views are also checked against Postgres's own parse of the query, and `E'…'` and dollar-quoted strings no longer hide column names from the check.
- **Writes reported saved that SQLite had rolled back** now fail, and their side effects don't run. Writes outside the record path, such as password resets, sign-outs and revocations, can't be lost with a rolled-back group.
- **The rule engine denies wherever it can't match the database exactly.** On Postgres that covers locale case folding, numbers inside JSON and nested JSON. Group dates, colors and sign-up fields are now normalised before rules see them.
- **Request costs:**
  - Thumbnails decode in a bounded queue and answer 503 when it is full. Each source is read once and capped at 64 MiB.
  - Creates sent to `/api/<col>/` or as relative batch URLs count against the create limit.
- **Installers and image:**
  - The installers verify the release signature by default when `cosign` is installed, check `--version`, and a truncated download runs nothing.
  - The Docker image is signed.

## Fixed

- **The dashboard could make the admin show "unreachable" for seconds.** The log reader re-parsed every day file on each load once logs spanned more than four days. It now keeps the newest days parsed, yields to other requests while it reads, and shares one read between concurrent requests.

## SDKs

No SDK release is needed. JS SDK 0.10.0, and Dart `vaultbase` 0.6.0 with `vaultbase_flutter` 0.1.5, work with this release.

## Upgrade notes

- **A restore keeps credentials and email changed since the backup.** To undo one, change it back after the restore.
- **Changing a table that a view reads can be refused (409)** while the view would expose a private column. Change or delete the view first.
- **Admin-only singletons and views answer 404 to non-admins.** File routes do the same for hidden collections.
- **File download tokens stop working when the session that minted them ends.**
- **Rules see group dates as Unix seconds and colors in their stored form.** A rule written against raw ISO strings or uppercase hex now behaves differently.
- **An admin whose session was reset since sign-in** can't mint API tokens or impersonate until they sign in again.
- **Thumbnails can answer 503** under heavy load.
- **With `cosign` on the PATH, installers verify signatures by default.** Installing an old unsigned release then needs `--no-verify-sig` (`-NoVerifySig`).
- If you are coming from before [v0.38.0](https://github.com/vaultbase-sh/vaultbase/releases/tag/v0.38.0), its upgrade notes apply too.
