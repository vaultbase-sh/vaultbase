## Security fixes, and docs checked against the code

v0.26.3 comes out of checking every page of the documentation against a running server and the SDK. That turned up about thirty places where the code didn't do what it should. Several are security fixes; upgrading is recommended.

## Security

- **Rules read a missing value the same way for one record as for a list.** A rule like `status != "secret"` hid a record with no status from lists but let it through on view by id and on realtime. Comparisons with a missing value are now false in both, as in SQL.
- **List totals no longer go stale under rules that read other collections** (`@collection.*`), which kept counting rows the caller could no longer see.
- **Every admin write is audited.** Settings, hooks, routes, jobs, admins, backups, indexes and collection changes were never recorded.
- **A failed `vaultbase backup` to S3, R2 or B2 leaves no database copy behind** in the data directory.

## Fixes

- **API tokens work as the docs show them** (`Bearer vbat_…`) on records, files, batch, custom routes, notifications and realtime. Admin REST routes still take only an admin session; automate admin work through MCP.
- **Collections:** deleting by name deletes the collection (it used to drop the data and keep the collection). System field names are refused, a table that can't be made rolls the collection back, singletons can have required fields, a field type change is a 422, and rules that don't parse are refused at save.
- **`created` / `updated` work in filters and rules**, as in `sort`.
- **Custom routes can return a `Response`**, `.txt` / `.json` uploads work, and rate-limit rules labelled `/api/v1/...` match.
- **Webhook test fires** reach only that webhook. **Notification** inbox rows go out over realtime, and FCM retries only the devices that failed.
- **MCP `update_setting`** validates like the REST API; **log JSONPath filters** like `$[?(@.status >= 400)]` match; an **encrypted value that won't decrypt** reads as null instead of failing the request.

## SDK

- **0.7.3:** one client no longer signs out another or receives another user's token (a shared BroadcastChannel is gone), and scripts that create a client exit normally. `vb.flags` sends the session, a dropped SSE stream reconnects, a caller's `AbortSignal` throws kind `aborted`, and `vb-types` types auth records as the server returns them.

## Upgrade notes

- **File fields:** a non-admin can only set a file field to files uploaded to that same record and field (422 otherwise). Upload to the record, then set the field, as before.
- **Field names** `id`, `created`, `updated`, `created_at`, `updated_at`, `collectionId`, `collectionName` and `expand` can no longer be added to a collection.
- **Rules that don't parse** are refused when you save them. Rules already saved keep working as before (they denied everyone).
- **SDK 0.7.3:** `vb.subscribe(name, "*")` callbacks receive only that collection's events (use `vb.subscribe("*", "*")` for all). Generated auth record types have `email_verified` (0/1) instead of `verified`.
