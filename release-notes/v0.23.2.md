## Read workers come back after an overload

v0.23.2 fixes how the read worker pool handles a worker that falls behind. No configuration changes.

## Fixes

- **Read workers come back after they are dropped.** A read worker that stopped answering was dropped and never replaced, so one overload spike left every read on the main thread until the server was restarted. A dropped worker is now replaced after a second, waiting longer (up to a minute) while replacements keep failing. The server logs each restart, and the Monitoring page shows how many workers were restarted.
- **A busy read worker is no longer mistaken for a stuck one.** A request that waits 30 seconds still fails with a 503, but its worker is dropped only when it has answered nothing at all for that long. A worker that is behind under load and still answering stays.
