## Postgres (beta)

v0.23.0 can run on Postgres instead of the SQLite file. SQLite stays the default and needs nothing; an existing install upgrades in place at the next start, with no configuration changes.

## Added

- **Postgres (beta).** Set `VAULTBASE_DATABASE_URL=postgres://…` and point it at an empty database: the schema is created at start and kept up to date. Records, rules, filters, full-text search, expand, batch, history, files, auth, admin, MCP, hooks and realtime work the same, and so do index suggestions, the Monitoring page, `strftime()` in filters and backups (through `pg_dump`). The full test suite runs against Postgres 16 in CI.
- **Several servers on one Postgres database.** A change made through one server (a collection, a rule, a field, a hook, a setting) takes effect on the others within milliseconds, realtime subscribers on every server hear about every write, and servers that start together take turns upgrading the schema. Every server needs the same `VAULTBASE_JWT_SECRET` and `VAULTBASE_ENCRYPTION_KEY`, and uploaded files need shared storage (S3).
- **`helpers.sql` in hooks, routes, jobs and workers.** Asynchronous SQL with `?` placeholders on either database: `query`, `queryOne`, `exec` and `transaction(fn)`. `helpers.db` keeps working on SQLite and is deprecated.

Not on Postgres yet, each answering with a clear error: restore from the backups page (use `pg_restore` with the downloaded `.dump`), the SQL sandbox (read-only queries work) and read worker threads. There is no built-in tool yet to move an existing SQLite install to Postgres; the Databases page describes doing it by hand.

## Changes

- **A schema change is one transaction.** Adding, renaming or dropping fields and renaming a collection either complete or leave the table as it was.

## Fixes

- **Decimal and negative numbers in filters and rules.** `price >= 10.5` and `price < -3` work in `?filter=` and in rules.
- **`geoDistance()` with literal coordinates** no longer fails with a parameter-count error.
- **Backups right after the index-suggestions report** no longer fail with "SQL statements in progress".
- **Writes made while a batch was running.** A setting saved or a session revoked by another request during a batch could be undone if the batch failed; they now wait for it.
