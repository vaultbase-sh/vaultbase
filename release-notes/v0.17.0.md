## Security hardening

v0.17.0 is a security release. It closes a long list of access-control, authentication and deployment issues found in an audit and a penetration test, and changes several defaults. **Upgrade, and read the upgrade notes first** — some apps will need small changes, and the SDK must be updated to `@vaultbase/sdk` 0.6.0 for OAuth sign-in to keep working.

## Security fixes

- **Access control.** New collections were public by default; they are now admin-only. Filters, sorting, aggregates and views could read hidden columns such as password hashes. Rules couldn't see the request body, update rules only checked the old record, `expand` and relations ignored the related collection's rules, and cascading deletes could remove other users' records. Record history, protected files, upload targets, feature-flag evaluation and the collections API are now checked properly.
- **Uploaded files** could run as pages on the API's own origin; they are now served as downloads with a sandboxing CSP.
- **Sign-in.** OTP codes, MFA codes and passwords could be guessed without limit; there is now a per-account lockout (on by default), attempt limits that can't be reset by signing in again, and per-address email cooldowns. Refreshing a token now revokes the old one, and sessions have a maximum age. One-time tokens are stored hashed. A stolen session can no longer replace a TOTP secret or mint recovery codes.
- **OAuth** sign-in skipped MFA and didn't verify its own `state`; the state is now server-side and bound to the browser, OIDC uses a nonce, and redirect URIs default to your app's origin.
- **Admin.** Any admin could take over another admin's account. The SQL runner's time limit never worked. The settings API returned every secret in plaintext; secrets now read back masked and are encrypted at rest by default.
- **Network.** The hook egress filter could be bypassed (IPv6 forms, redirects, DNS); the client IP could be spoofed with `X-Forwarded-For`; admin and auth responses could be cached; the rate limiter was easy to sidestep; `/metrics` was public when enabled.
- **Install and operations.** A fresh install could be claimed by whoever reached it first; first-admin setup now needs a setup key. `vaultbase update` could install an unsigned release. Data files were world-readable outside the installer. A backup restore revived revoked sessions.
- **Realtime** connections outlived their credentials and had no limits; they are now re-checked every minute and capped.

## Fixes

- Shutdown waits for in-flight requests and running jobs; jobs interrupted by a crash are recovered.
- Migrations report failures instead of hiding them.
- Read-only `/batch` requests no longer block writes; vector search accepts `nearLimit` above 25.
- The hosted magic-link page works for accounts with two-factor sign-in.
- Installer fixes for Alpine, argument parsing and env-file permissions.

## New

- **`color` field type** — a hex color stored as lowercase `#rrggbb` (optional alpha), with a picker in the admin.
- **Rules can tell users apart**: `@request.auth.collectionName`, `@request.auth.verified`, `@request.auth.anonymous`.
- **Custom routes** can require sign-in.
- **Audit-log retention** (`audit.retention_days`).
- **Windows installer** and platform detection in `install.sh`.
- **Redesigned admin**, with windowed queue and collection stats.
- SDK (`@vaultbase/sdk` 0.6.0): OAuth `state_secret` handling, MFA results from OAuth, `recoveryRegenerate(code)`, realtime re-authentication, and a fix for requests hanging when the token was about to expire.

## Upgrade notes

See the full list in the [changelog](https://github.com/vaultbase-sh/vaultbase/blob/main/CHANGELOG.md). The ones most installs will notice:

- **Collection rules left unset are admin-only**, not public. Set rules explicitly for collections that should be readable.
- **First-admin setup needs a setup key**, printed at startup (or `VAULTBASE_SETUP_KEY`).
- **An encryption key is generated** in `<dataDir>/.encryption-key` when `VAULTBASE_ENCRYPTION_KEY` isn't set. Back it up with your database.
- **Secret settings read back as `********`.**
- **OAuth needs the server-issued `state` and `state_secret`** at the exchange; update the SDK to 0.6.0.
- **Sign-in lockout is on by default** for admins and users.
- **Custom routes are rate limited** and return a generic `500` on errors.
- **Client filters may use one `@collection.*` / `_via_` reference.**
- **Cluster mode is for stateless REST scaling**: caches, realtime and rate limits are per worker, and online restore is disabled.
- **Behind a reverse proxy, set `security.trusted_proxies`** so client IPs, rate limits and secure cookies work.
